# Nikon Z50II 交互式精细拆解模型设计

- 日期：2026-08-25
- 状态：设计已在对话中逐节确认，待用户审核本文档
- 交付目标：Blender 源工程与可离线运行的浏览器交互成品

## 1. 项目目标

制作一套高写实、可操作的 Nikon Z50II 机身三维拆解模型。用户可在浏览器中旋转、平移和缩放相机，按教学步骤播放拆解动画，也可选择零件并沿限定方向自由移动。Blender 源工程保留完整零件层级、PBR 材质、灯光、拆解动画和可重复导出的模块结构。

项目优先满足以下目标：

1. 外观比例、控制布局和主要表面特征高度接近 Nikon Z50II。
2. 内部组件依据公开维修资料建立可信的参考级结构与拆解关系。
3. 提供约 70–100 个可选择对象，覆盖主要零件、排线、屏蔽件和紧固件。
4. 同时支持步骤引导拆解与受约束的自由拆解。
5. 在 Blender 与浏览器中呈现可信的 PBR 材质、光影、反射和接触阴影。
6. 采用模块化多 GLB 结构，便于按需加载和后续增加镜头模块。

## 2. 范围与精度声明

### 2.1 本期范围

- Nikon Z50II 机身外观与内部参考级结构。
- Z 卡口、电子触点和镜头挂接坐标原点。
- 机身拆解动画、零件元数据和浏览器交互。
- 中文为主、英文为辅的零件名称与说明。

### 2.2 本期不包含

- 镜头内部结构；仅保留后续挂接和扩展能力。
- 制造级公差、模具结构、材料认证或原厂内部 CAD 数据。
- 可用于真实维修或制造的尺寸保证。
- 自由刚体物理仿真、软体排线物理或碰撞驱动装配。
- 公网部署；默认交付本地离线版本。

### 2.3 参考基准

- 外形基准采用 Nikon 公布的约 127 × 96.8 × 66.5 mm 机身尺寸、Nikon Z 卡口、DX 画幅传感器和 3.2 英寸翻转屏。
- 外部形态与按键布局参考 Nikon 官方产品页和用户手册。
- 内部层级与拆解顺序优先参考 Nikon 官方 Self Service Repair 维修手册。
- 无公开资料覆盖的内部细节按相机工程结构合理化重建，并在网页说明中标记为“参考级模型”。

## 3. 交付物

### 3.1 Blender 交付

- `z50ii_master.blend`：完整主工程，包含统一坐标、Collections、对象命名、材质、灯光、相机和拆解动画。
- `textures/`：PBR 贴图和品牌/按键贴花源文件。
- `scripts/export_modules.py`：按 Collection 导出模块 GLB 并生成装配清单的脚本。
- `renders/`：摄影棚灯光下的装配态与爆炸态参考渲染。

### 3.2 浏览器交付

- 可离线运行的静态 Web 工程。
- 多个模块化 GLB、压缩贴图和 HDR 环境资源。
- `assembly-manifest.json`：零件层级、名称、拆解轴、距离、步骤和依赖关系。
- 中文界面、操作说明和本地启动脚本/说明文档。
- Chrome 与 Edge 的桌面端验证记录。

## 4. 模型架构

`z50ii_master.blend` 是唯一模型真源。所有对象使用一致的世界原点、轴向和单位；GLB 仅为发布产物，不在导出后手工修改。

模型按以下 Collection 分组并分别导出：

1. `01_chassis_front`：承力骨架、前机壳和握柄基础结构。
2. `02_outer_shell_controls`：外壳蒙皮、蒙皮贴片、拨轮、按钮和舱门。
3. `03_mount_shutter_sensor`：Z 卡口、触点、快门、传感器和防尘相关结构。
4. `04_mainboard_thermal`：主板、处理器、屏蔽罩、导热件和散热片。
5. `05_power_storage`：电池仓、EN-EL25a 外形占位、电源板和 SD 卡槽。
6. `06_evf_top_flash`：EVF、热靴、顶部控制和内置闪光灯机构。
7. `07_rear_lcd_controls`：后盖、翻转屏、转轴、方向键和后部控制件。
8. `08_io_flex_fasteners`：接口板、无线组件、排线、螺钉、垫圈和支架。

重复紧固件采用链接对象或实例化方式，浏览器中仍保留独立可选择 ID。主零件采用独立几何，排线使用带厚度的简化曲面，避免不可控的软体仿真。

## 5. 命名与零件元数据

对象命名采用稳定 ID，不使用仅供显示的中文名称作为主键。例如：

```text
Z50II-03-014_sensor_cover_glass
Z50II-04-006_main_pcb
Z50II-08-031_rear_shell_screw_m2
```

每个可交互对象至少包含：

- `partId`：全局唯一 ID。
- `nameZh`、`nameEn`：中英文名称。
- `moduleId`：所属 GLB 模块。
- `parentId`：装配层级父对象。
- `step`：引导拆解步骤。
- `explodeAxis`：世界或局部坐标中的限定移动轴。
- `explodeDistance`：最大拆解位移。
- `dependsOn`：移动前必须完成拆解的零件 ID。
- `descriptionZh`、`descriptionEn`：功能与参考级说明。
- `isReferenceGeometry`：是否属于合理化重建的内部结构。

`assembly-manifest.json` 是浏览器交互的唯一规则来源。依赖关系必须构成有向无环图。

## 6. 拆解交互

### 6.1 引导拆解模式

- 播放、暂停、上一步、下一步和时间轴拖动。
- 全局爆炸程度滑块可在装配态与完整爆炸态之间连续过渡。
- 当前步骤自动高亮目标零件，绘制移动方向，并将相机平滑调整至合适视角。
- 拆解动画使用缓入缓出；紧固件、外壳和内部模块按依赖顺序运动。
- 用户可随时暂停并检查零件信息，然后继续播放。

### 6.2 自由拆解模式

- 光线拾取选择零件；选中后显示名称、说明和允许的移动方向。
- 零件仅能沿配置的局部或世界轴移动，可通过拖动操纵轴或数值滑块操作。
- 未满足 `dependsOn` 时锁定移动，并说明需要先移除的组件。
- 提供隐藏、隔离、透明显示、复位和撤销最近移动。
- 不使用通用刚体物理；稳定性由限定轴、位移范围和依赖锁控制。

### 6.3 通用视图功能

- 轨道旋转、平移、滚轮/手势缩放和视图复位。
- 前、后、左、右、顶部和三分之四视角预设。
- 剖切平面用于观察内部组件。
- 摄影棚灯光与检查灯光两种预设。

## 7. 浏览器界面

- 左侧：可搜索的装配树、模块加载状态、隐藏与隔离控制。
- 中央：3D 视窗、选择高亮、方向操纵轴和剖切平面。
- 右侧：中英文零件名称、功能说明、拆解状态和依赖提示。
- 底部：模式切换、播放控制、步骤时间轴和全局爆炸滑块。
- 桌面优先；窗口变窄时左右面板可折叠，不把移动端作为主要验收平台。

## 8. 写实材质与光影

### 8.1 材质

- 黑色工程塑料与金属机壳：独立控制粗糙度、微表面法线和边缘磨损强度。
- 橡胶握皮：颗粒高度、粗糙度变化和低强度色差。
- Z 卡口、螺钉和屏蔽件：物理金属反射、各向同性高光和细微加工纹理。
- 屏幕、EVF 和传感器盖玻璃：多层高光、适度透射/清漆效果和轻微光学色变。
- 品牌、按键和接口符号：贴花或纹理图集，不依赖漂浮文字几何。

### 8.2 Blender 灯光

- Cycles 作为参考静帧渲染器。
- HDRI 环境提供自然反射，辅以产品摄影级主光、柔和补光和轮廓光。
- 使用真实尺度、接触阴影和合理曝光；装配态与爆炸态共享一致的色彩管理。

### 8.3 浏览器灯光

- 使用物理正确材质与光照、HDR 环境贴图和 ACES 色调映射。
- 摄影棚模式突出真实反射与轮廓；检查模式提高内部零件可读性。
- 开启软阴影和环境遮蔽；按性能档位调整阴影分辨率、AO 和反射质量。

## 9. 数据与运行流程

1. 在 Blender 主工程中创建或修改零件。
2. 通过对象自定义属性维护 ID、名称、拆解轴、距离、步骤和依赖。
3. 导出脚本校验命名、坐标、重复 ID、依赖循环和贴图引用。
4. 每个顶层 Collection 导出为独立 GLB，同时生成统一装配清单。
5. 浏览器先加载清单和轻量外壳模块，再按装配树或拆解步骤加载其余模块。
6. 所有 GLB 对齐到共享世界原点；运行时不进行人工对位补偿。
7. 引导模式和自由模式读取同一份拆解规则，避免两套逻辑漂移。

## 10. 性能策略

- 使用模块按需加载，初始只加载外观和交互所需的最小资源。
- 为高细节和检查模式提供至少两档几何/贴图质量配置。
- 主外壳和近距离重点零件保留真实倒角；细小重复纹理由法线贴图承担。
- 螺钉、垫圈等重复几何实例化；不可见内部模块延迟加载。
- 浏览器优先使用压缩纹理与压缩网格，但保留未压缩发布源用于排错。
- 以硬件加速 WebGL2 桌面浏览器为目标，在 1080p 常规视角下争取不低于 45 FPS；验收时记录实际测试设备与结果，不把该目标解释为所有硬件上的保证。

## 11. 容错与降级

- GLB 加载失败时在装配树显示失败模块，并提供重试。
- 缺失贴图使用明确的备用材质，同时记录资源路径错误。
- 清单格式、重复 ID 或依赖循环错误会阻止发布构建并给出可定位信息。
- 浏览器不支持所需 WebGL 能力时显示兼容性提示，不进入损坏的交互状态。
- 交互状态异常时可一键复位全部零件、相机、剖切和平面透明度。
- 高质量阴影、AO 或 HDR 失败时降级到基础 PBR 光照，拆解功能保持可用。

## 12. 验证与验收

### 12.1 自动验证

- 所有模块通过 glTF/GLB 结构验证。
- 全部 `partId` 唯一且在模型和清单之间一一对应。
- 所有模块世界坐标一致，装配态无明显错位。
- 拆解依赖无循环，引用的零件 ID 均存在。
- 贴图、HDR 和 GLB 路径完整；离线构建不请求外部资源。
- 浏览器生产构建与基础交互测试通过。

### 12.2 人工验收

- Z50II 外观比例、主要按键、卡口、屏幕、EVF、闪光灯和接口具有明确辨识度。
- 约 70–100 个对象可从零件树或 3D 视窗选择。
- 引导拆解可从完整装配态运行到完整爆炸态并返回。
- 自由拆解遵守移动轴、位移范围和依赖锁，不出现明显穿模。
- 透明、隔离、剖切、灯光切换和复位功能可用。
- Blender 与浏览器中的材质观感一致，金属、橡胶、塑料和玻璃可明确区分。
- 摄影棚光照具有自然高光、轮廓光和接触阴影；内部检查灯光能看清结构。
- Chrome 与 Edge 桌面端均可完成核心操作。

## 13. 风险与控制

- **内部资料不完整**：以官方维修资料优先；合理化重建部分统一标记为参考级。
- **精细模型导致性能下降**：多 GLB、实例化、LOD、纹理压缩和按需加载共同控制。
- **Blender 与网页材质差异**：采用金属度/粗糙度 PBR 工作流，并以固定校准场景进行对照。
- **自由拆解产生穿插**：不依赖自由物理，使用明确拆解轴、位移范围和前置依赖。
- **后续镜头扩展破坏机身工程**：镜头使用独立 GLB、独立清单段和已冻结的 Z 卡口挂接坐标。
